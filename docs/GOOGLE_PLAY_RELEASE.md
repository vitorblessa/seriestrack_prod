# Google Play Release Workflow — SeriesTrack

End-to-end guide to build, sign and publish the Android bundle.

## 1. Pre-requisites (host machine, not this container)

- **JDK 21 LTS** (`brew install openjdk@21` on macOS, or via SDKMAN)
- **Android Studio Ladybug** (2024.2.1) or newer — installs the SDK + Platform 36
- **Android SDK Platform 36** (Android 16)
- **Android SDK Build-Tools 36.0.0+**
- **Node 20+** (already used in this repo)
- **Yarn 1.22+**

Export in your shell (`~/.zshrc` / `~/.bashrc`):

```bash
export ANDROID_HOME=$HOME/Library/Android/sdk        # macOS default
export PATH=$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin
export JAVA_HOME=/opt/homebrew/opt/openjdk@21
```

## 2. Repository layout

```
frontend/
├── capacitor.config.ts        ← webDir=build, appId=com.vitorblessa.seriestrack
├── .env.production            ← REACT_APP_BACKEND_URL for the release bundle
├── build/                     ← CRA output (generated by `yarn build`)
└── android/                   ← Native Android project (Capacitor 7)

        └── src/main/res/xml/network_security_config.xml
```

## 3. Environment variables required for a signed release

| Variable | Where | Notes |
| --- | --- | --- |
| `ANDROID_KEYSTORE_PATH` | Shell | Absolute path to `.jks` (never commit) |
| `ANDROID_KEYSTORE_PASSWORD` | Shell | Store password |
| `ANDROID_KEY_ALIAS` | Shell | Key alias inside the keystore |
| `ANDROID_KEY_PASSWORD` | Shell | Key password (usually same as store password) |
| `REACT_APP_BACKEND_URL` | `frontend/.env.production` | Already set to `https://show-notify.emergent.host` |

The Gradle `signingConfigs { release }` block reads these at build time.
If they're absent, Gradle falls back to the debug keystore — safe for local testing only.
**Never publish a debug-signed APK/AAB.**

## 4. Generate a keystore (one-time, per developer)

```bash
keytool -genkey -v \
  -keystore ~/.keystores/seriestrack-release.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias seriestrack
```

Answer the prompts. Keep the resulting `.jks` **and** its password in a password manager. If you lose it, Google Play Console can rotate the upload key via [Play App Signing](https://support.google.com/googleplay/android-developer/answer/9842756) — but the app must already be enrolled.

**Enable Play App Signing** on the first upload — Google stores the app-signing key, you keep the upload key. Recommended.

## 5. Build the release bundle

```bash
cd frontend

# 1. Build web assets pointing at the production backend
yarn build

# 2. Copy assets + plugin config into android/
npx cap sync android

# 3. Assemble the AAB
cd android
./gradlew clean
./gradlew bundleRelease
```

Output: `frontend/android/app/build/outputs/bundle/release/app-release.aab`

### 5a. Alternative: build via GitHub Actions (recommended)

The repository ships a workflow at `.github/workflows/android-release.yml` that builds a signed AAB automatically. **You never need to install JDK/Android SDK locally.**

**One-time setup** — Settings → Secrets and variables → Actions → New repository secret:

| Secret | Value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 seriestrack-release.jks` output |
| `ANDROID_KEYSTORE_PASSWORD` | Your keystore password |
| `ANDROID_KEY_ALIAS` | e.g. `seriestrack` |
| `ANDROID_KEY_PASSWORD` | Alias password |
| `REACT_APP_BACKEND_URL` | `https://show-notify.emergent.host` |
| `PLAY_SERVICE_ACCOUNT_JSON` (optional) | Play Console API service account JSON for auto-upload |

**Trigger a release build:**

```bash
# Bump version in frontend/android/app/build.gradle first
git tag v1.0.0
git push origin v1.0.0
```

The workflow will:
1. Install Node 20, JDK 21, Android SDK 36, Gradle
2. Run `yarn build` with your production `REACT_APP_BACKEND_URL`
3. Run `npx cap sync android`
4. Decode the keystore from the base64 secret
5. Run `./gradlew bundleRelease` with signing
6. Upload the AAB as an artifact (30-day retention)
7. Upload `mapping.txt` for R8 deobfuscation (90-day retention)
8. If `PLAY_SERVICE_ACCOUNT_JSON` is set → upload to Play Console Internal track as draft

**Manual trigger** (Actions tab → "Android Release Build" → Run workflow): supports optional `versionName` / `versionCode` overrides without editing gradle.

## 6. Test the AAB locally with bundletool

```bash
brew install bundletool
bundletool build-apks \
  --bundle=app-release.aab \
  --output=app-release.apks \
  --ks=$ANDROID_KEYSTORE_PATH \
  --ks-key-alias=$ANDROID_KEY_ALIAS \
  --ks-pass=pass:$ANDROID_KEYSTORE_PASSWORD \
  --key-pass=pass:$ANDROID_KEY_PASSWORD
bundletool install-apks --apks=app-release.apks
```

Or upload directly to Play Console's Internal Testing track — Google handles the split APK generation.

## 7. Play Console flow

1. Create app at [play.google.com/console](https://play.google.com/console) → package `com.vitorblessa.seriestrack`.
2. **Internal testing** track → upload the AAB → add 1–5 tester emails.
3. Fill mandatory forms:
   - **Data safety** — copy from `docs/google-play-data-safety.md`
   - **Content rating** — questionnaire (SeriesTrack is likely PEGI 3 / everyone)
   - **App access** — provide `admin@seriestrack.app` / `Admin@123` test credentials
   - **Target audience** — 13+
   - **Privacy policy URL** — `https://show-notify.emergent.host/privacy`
   - **Account deletion URL** — `https://show-notify.emergent.host/delete-account`
4. Store listing:
   - App icon: `docs/play-store-assets/icon-512.png`
   - Feature graphic: 1024×500 PNG (**TODO — create and drop into `docs/play-store-assets/`**)
   - Phone screenshots ×4–8 (min 320px, max 3840px)
5. Submit for review.

## 8. Version bumps

Every new build to Play Console requires a higher `versionCode`. Recommended scheme:

```
versionName = "1.0.0"           # SemVer, visible to users
versionCode = 1                  # Monotonically increasing integer
```

For every release, in `frontend/android/app/build.gradle`:

```groovy
versionCode 2      // bump by 1 each upload
versionName "1.1.0"
```

Or set via env for CI:

```groovy
versionCode System.getenv("ANDROID_VERSION_CODE")?.toInteger() ?: 1
versionName System.getenv("ANDROID_VERSION_NAME") ?: "1.0.0"
```

## 9. Push notifications (optional — Firebase)

Currently the app uses Web Push via VAPID. To publish push on Android natively:

1. Create Firebase project → add Android app with package `com.vitorblessa.seriestrack`.
2. Download `google-services.json` → drop into `frontend/android/app/`.
3. Add `@capacitor/push-notifications` plugin and register the FCM token with the backend.
4. Backend already stores subscriptions in `db.push_subscriptions` — extend to accept FCM tokens alongside Web Push endpoints.

**Not blocking for first release** — the app works fine with browser-based Web Push on Android.

## 10. Emergent-specific notes

- The backend at `https://show-notify.emergent.host` is deployed via the Emergent pipeline. Any change to `/app/backend/` requires a redeploy before it's live for the Android WebView.
- CORS: set `CORS_ORIGINS=https://show-notify.emergent.host` in the production env (see `docs/GOOGLE_PLAY_CHECKLIST.md`).

## 11. Emergency: rotate signing key

If your upload key is compromised, follow [Play Console → App integrity → App signing → Request upload key reset](https://support.google.com/googleplay/android-developer/answer/9842756).
Google will accept a new key within 48h.
